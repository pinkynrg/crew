how it's built

Small on purpose.

crew owns the fan-out (parallelism, labelled output, teardown) and the wiring, and never interprets your tasks beyond one placeholder. Everything else is yours. No runtime dependencies, no build step, no bundler: the source is what runs.

get started

From zero to a running set.

  1. Install 
    $ npx @pinkynrg/crew

    Zero dependencies, so it lands instantly. Or install it globally with npm i -g @pinkynrg/crew.

  2. Point at your repos 
    $ crew dir ~/Projects

    Where your project folders live; relative paths in your config resolve against it.

  3. Register a project 
    $ crew add

    A short wizard: its path, its start command, and the host(s) it's served under (so crew can wire it).

  4. Run the set 
    $ crew start env=production

    Pick a connected slice in the dependency graph (click or arrow keys); crew runs those locally, wires them together, and leaves the rest on their resolved remote env.

  5. Open the set as one window 
    $ crew workspace

    Every picked repo in a single VS Code workspace.

  6. Hand the set to Claude Code 
    $ crew claude

    One session across the group, with history kept per set.
